The demo on the home page follows one rule. A product definition has many: actors, journeys,
use cases, business rules, domain terms, requirements and the behaviours that pin them down,
all linked by typed relationships.

This is a whole one for a small online shop. It has {provenance.artifacts} artifacts and
{provenance.relationships} relationships, and it includes `BR-REFUND-001`, the refund rule from
the demo. The page is one self-contained HTML file generated from the model's Markdown. It is
read-only, it works offline and it stores nothing.

</LinkButton>

## Things to try

- Search for `BR-REFUND-001` and follow it to the use cases it applies to.
- Open the journey "Get money back" and walk its steps.
- Read how each kind of artifact connects to the others, then open a cell to see which artifacts
  sit behind a number.
